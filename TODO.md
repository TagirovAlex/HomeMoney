# 📋 TODO.md: Список и очередность задач по разработке

Этот план определяет фазы разработки, обеспечивая постепенное наращивание функциональности от ядра к внешним интеграциям. Все задачи должны быть выполнены с соблюдением архитектурных паттернов (Repository Pattern, Service Layer).

### Phase 0: Setup & Infrastructure (MVP Foundation)
*(Цель: Создание рабочего окружения и базы данных)*
*   [ ] **Setup:** Инициализация проекта Python, настройка виртуального окружения.
*   [ ] **DB Schema:** Разработка схемы БД (User, Account, Category, Transaction).
*   [ ] **Backend Core:** Настройка минимального каркаса Flask/FastAPI.
*   [ ] **Repository Layer:** Создание и Unit-тестирование репозиториев (`UserRepo`, `AccountRepo`, `TransactionRepo`).

### Phase 1: Core Business Logic & CRUD (The Backbone)
*(Цель: Обеспечить возможность проведения базовых финансовых операций)*
*   [ ] **Authentication Module:** Реализация регистрации, входа и ролевого контроля доступа.
*   [ ] **Account Management Service:** Сервис для управления активами (создание/получение баланса с начальным остатком).
*   [ ] **Core Transaction Service (Service Layer):** Главный сервис `FinancialService`. Реализация транзакционной логики: проверка баланса, фиксация записи, корректировка балансов.
*   [ ] **Web UI (Basic):** Создание минимального веб-интерфейса для ручного ввода данных и проверки базовой работоспособности ядра.

### Phase 2: User Experience & Advanced Logic
*(Цель: Улучшение UX и добавление сложных финансовых правил)*
*   [ ] **UI/UX Implementation:** Разработка адаптивного фронтенда (Mobile-First).
    *   [ ] Внедрение Dark Mode / Light Mode переключателя.
    *   [ ] Оптимизация форм ввода данных для максимальной простоты использования.
*   **Budgeting Module:** Реализация сервиса расчета и визуализации лимитов по категориям.
*   **Recurring Payments:** Создание логики планирования регулярных платежей в календаре/списке.
*   **Reporting & Dashboard:** Разработка модуля аналитики, отображающего ключевые метрики (общий баланс, графики Net Flow).

### Phase 3: External Integration (Telegram Bot - High Priority)
*(Цель: Расширение доступности системы)*
*   [ ] **Admin Configuration:** Создание интерфейса Админа для привязки `Telegram User ID` к системным пользователям.
*   [ ] **Bot Infrastructure:** Настройка асинхронного хендлера с использованием `aiogram` v3.
*   [ ] **Bot State Machine (Core Flow):** Разработка логики диалога пользователя: Выбор типа $\to$ Категория $\to$ Счет $\to$ Сумма. Этот поток должен вызывать и проверять `FinancialService`.
